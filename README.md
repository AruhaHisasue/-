# 個別支援計画作成ソフト MVP

Windows向け・オフライン。Python 3.12 / PySide6 / SQLite / openpyxl。

## 起動

ビルド済み：`dist/IndividualSupportPlan/IndividualSupportPlan.exe` を起動してください。
配布するときは **IndividualSupportPlanフォルダー全体** が必要です。exeだけを移動しないでください。

ソースから起動する場合（PowerShell、プロジェクト直下）：

```powershell
uv python install 3.12
uv venv --python 3.12 .venv
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
.venv/Scripts/python.exe app.py
```

Python 3.12以降が既にある場合は `python -m venv .venv` と `.venv/Scripts/python.exe -m pip install -r requirements.txt` でも準備できます。APIキーは不要です。

## 操作

タブは2段です。上段は「基本情報 / アセスメント / 算定・報酬 / 変更履歴・設定」、下段は工程の「モニタリング / 仮計画 / 本計画 / 担当者会議」です（旧「計画案」は仮計画、旧「計画」は本計画に改称）。起動時は基本情報を表示します。各工程の記録日・作成日が先行工程より前の場合、日付フォーム右側に赤字警告を表示します。未入力日は比較せず、同日は許容します。期間は開始・終了の前後関係を別に確認します。警告だけでは一時保存を妨げません。

基本情報タブは「利用者・事業所」「計画の期間・進捗」「担当サービス管理責任者：初回登録」「担当サービス管理責任者：担当変更」に分けて配置しています。

- 利用者氏名・事業所名を入力して「基本情報を確定」を押すと、会議録の利用者氏名と、モニタリング・仮計画・本計画・担当者会議の事業所名へ自動入力します（各タブの既存値は上書き）。氏名・事業所名を変えた場合は再度確定してください。
- 「初回登録」は未登録時のみ使用でき、名前と担当開始日を `managers.sqlite` に保存し、各タブのサービス管理責任者欄へ入力します。
- 「担当変更を保存」は初回登録後のみ使用できます。過去の書類の担当者名を守るため、各タブの欄は自動では書き換えません。各タブのサービス管理責任者欄の横にある「サビ管名を転記」で現在の担当者を入力してください。
- 同じ担当者での再登録は履歴を追加しません。登録操作はDBに即時保存されます。計画ファイルも通常保存してください。

仮計画・本計画の留意事項横のボタンは、選択済み算定名のみを直接追記します。既存の文章は保持し、同じ算定名の行は重複させません。内容はフォーム上で修正できます。算定の確認済み状態は自動変更しません。

算定選択一覧の左端の☆をクリックすると★になります。★の項目は同じ一覧の先頭に固定表示され、検索条件外でも表示されます。★をクリックすると解除できます。既存のブックマークDBを引き継ぎます。

1. 基本情報で氏名などを入力します。日付は「入力」にチェックしてカレンダーから選択します。
2. アセスメント・仮計画/本計画・担当者会議の各項目を入力します。目標は各計画4枠です。
3. 「保存」で `.isp` に保存します。「開く」「名前を付けて保存」に対応。左の一覧は既定保存先のファイルと現在開いているファイルです。
4. 計画更新時は「前計画を複製して更新」を使います。同意と進捗は再確認します。保存時の理由・変更基準日・補足は「変更履歴 / 設定」で指定します。
5. 「Excel出力」で未記入原本を選択して出力します。記載例は比較検証専用です。
6. 「算定・報酬」で `resources/r806_fee_master_fixed.zip` を取り込み、サービス・分類・文字列で検索します。ID・版・マスタハッシュ・選択日時・適用日・理由を保存します。
7. 「印刷」でシートとExcelプレビュー、プリンター選択、PDF保存を選びます。プリンター選択はExcel標準ダイアログです。
8. モニタリングは計画の目標から作成し、実績・達成状況・対応方針・記録者・日付を保存します。

未入力時は原本表示を保持します。原本の提供時間は実績ではありません。提供時間は構造化入力と確認チェックがある場合だけ出力します。同意日も確認チェックが必要です。署名は生成しません。進捗を下書き以外にする場合は進捗の確認日が必要です（証跡・確認者欄は廃止）。

## 保存場所とセキュリティ

既定の保存先、マスタDB、一時保存は `%LOCALAPPDATA%/IndividualSupportPlan` です。`ISP_DATA_DIR` 環境変数で変更できます。60秒ごとの一時保存は `recovery/` に別ファイルとして残ります。「一時保存を復元」で読み、通常ファイルとして保存してください。

`.isp` はZIPで、manifest.json・project.json・attachments/metadata.jsonを格納します。添付本体は埋め込まず、名前・パス・ハッシュなどのメタデータを保存します。SHA-256は破損確認用で、改ざん防止署名ではありません。暗号化・パスワード・アクセス権管理・バックアップ管理・改ざん耐性のある監査ログは未実装です。**本番の個人情報を扱う前にこれらを実装してください。現段階はダミーデータで検証してください。** 一時保存にも同じ制限があります。

- `templates/個別支援計画書原本(令和6年 生活介護).xlsx`：比較検証用。受領した「個別支援計画書(令和6年 生活介護)_記載例.xlsx」のコピーです。
- `mappings/individual_support_excel_mapping.json`：転記先の唯一の正本。133項目。
- `mappings/個別支援計画_Excelセル対応表.xlsx`：人間向け対応表。
- `resources/r806_fee_master_fixed.zip`：再生成後に受領した正式取込元。旧ZIPは参照しません。

原本のハッシュが変わると安全のため出力を停止します。新しい帳票には専用のマップ・検証・テンプレート版の登録が必要です。シート名の末尾空白・全角空白は維持します。記入済み原本からの出力は無効です。

## Excel出力・印刷の確認

openpyxlで原本とマップを検査し、ZIP内部の許可セルの値だけを更新します。数式・固定セルは書換禁止。結合セル左上だけを許可し、5件目の目標は出力停止します。支援のポイントはD列本文に合成し、E14とE15:E17は保持します。日付セルだけ表示形式を追加し、文字列はExcel数式として解釈させません。

出力後は各シートで文字の収まり、目標4件、提供時間、責任者ラベル、同意日、改ページを確認してください。アセスメントA1:K40・会議録A1:L42は印刷用一時コピーだけに適用します。計画2シートの原本印刷範囲は保持します。Excel COMは専用インスタンスを使用し、終了時にブックを閉じExcelを終了します。Excel/pywin32がない環境では印刷を無効化し、出力.xlsxを互換アプリで開く方法を案内します。

## 制約・未実装

- R806は障害福祉の算定構造です。33サービス・5096項目を取込します。介護保険・別年度のマスタは未対応で、専用アダプターが必要です。
- 算定条件・併算定制限・地域単価・適用年月などの完全な規則は揃っていないため、算定可否と確定報酬額は計算しません。選択項目も「要確認」と表示します。
- モニタリングは受領した templates/モニタリング.xlsx に出力できます。専用マップは mappings/monitoring_mapping.json です。
- AIは独立インターフェースのみ。生成・API接続・外部送信は未実装です。
- 長文の自動組版・自動行高調整は行いません。実際のプレビューで担当者による確認が必要です。
- 提供されたマップには計画2シートの欄外「利用者氏名」「作成年月日」の転記先がありません。その欄は原本表示を維持します。基本情報の氏名はアセスメントと会議録へ転記されます。計画の欄外にも転記する場合は、セル対応表を正式に拡張して検証する必要があります。
- 実プリンターへの紙出力は未実施です。印刷ダイアログから実機で用紙・縮小率・欠けを確認してください。
- 複数人同時編集、利用者DB、検索可能な全保存先カタログ、添付本体の格納、暗号化と運用監査機能は未実装です。

## モニタリング様式・転記の更新

モニタリングは計画と共通のフォームを使用し、目標4枠では達成度（1～5）と今後の課題を入力します。従来形式の評価記録は同じタブの下部に保持します。モニタリングExcel出力ボタンで指定様式に出力できます。

仮計画の最上部「モニタリングの内容を転記」、本計画の最上部「仮計画の内容を転記」で共通項目（作成日・同意日を含む）を転記します。転記先の共通項目は空欄も含めて置換します。異なる書類タイトルと同意確認の証跡は引き継ぎません。達成度・今後の課題は計画側に同義の項目がないため転記しません。既存の支援期間・評価期間などモニタリング側にない項目は保持します。

留意事項横の「選択済みの算定名を入力」はチェックボックス画面を開きます。チェックした算定名だけを直接追記し、キャンセル時は変更しません。

モニタリング原本のセル外ヘッダーにある作成年月日（令和8年10月10日）は原本表示を保持します。フォームの作成日とは自動連動しません。出力時はヘッダーの日付を確認してください。

## 加算の変更履歴

算定・報酬タブで項目を選択すると「追加」、確認チェックの付け外しで「確認済み / 確認取消」、各項目の「算定終了を記録」（終了日・理由は必須、終了日は適用日以降）で「終了」を、`%LOCALAPPDATA%/IndividualSupportPlan/fee_history.sqlite` に記録します。

- 同タブ下部の「加算の変更履歴」に、この利用者の全計画分を適用日順で表示します。分類（加算 / 減算 / 基本報酬 / 注による調整 / 全分類）で絞り込めます。
- 利用者単位のID（metadata.subject_id）で管理するため、「前計画を複製して更新」した後も同じ履歴を表示します。
- 履歴DBの導入前に作成した `.isp` は、開いた時点で選択済み項目を「追加」として登録します（重複登録はしません）。
- 履歴はサビ管担当履歴と同じく即時記録で、計画ファイルを保存しなくても残ります。記録の修正・削除機能はありません。改ざん耐性はありません。
- 終了した項目は「選択済みの算定名を入力」の候補から外れます。
